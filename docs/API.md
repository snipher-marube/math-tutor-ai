# Backend API

Base URL in development: `http://localhost:8000`. Interactive docs, generated by FastAPI, are at `/docs` (Swagger) and `/redoc`.

## `GET /`
Liveness message.
```json
{ "status": "ok", "message": "math tutor AI is running" }
```

## `GET /health`
Health check for scripts and monitoring.
```json
{ "status": "ok" }
```

## Lesson API

The teaching engine: problems, answer checking and hints. No AI is used. The answer to a problem **never** goes to the browser. The server remembers each problem it hands out and checks the child's answer itself.

> Problems and answers are saved in the local database, so they survive a restart. Pass a `learner_id` to count the answers toward that learner's progress (see [Learners](#learners)).

### `GET /api/lesson/skills`
All skills, in teaching order (prerequisites first).
```json
[{ "id": "count-to-20", "name": "Count objects to 20", "grade": 1, "strand": "numbers",
   "substrand": "whole-numbers", "requires": [], "description": "...", "examples": ["..."] }, ...]
```

### `POST /api/lesson/problems`
A new problem for a skill. Returns `201`.
```bash
curl -X POST http://localhost:8000/api/lesson/problems \
  -H "Content-Type: application/json" -d '{"skill_id": "add-within-100-with-regrouping", "learner_id": 1}'
```
`learner_id` is optional. Without it, the problem is anonymous practice.
```json
{ "id": "4f70c7f0c8c4fe84", "skill_id": "add-within-100-with-regrouping",
  "kind": "add", "question": "78 + 12 = ?", "operands": [78, 12] }
```
`operands` are the numbers the screen shows, for drawing visuals. For counting problems (`kind: "count"`), the operand is the number of objects to draw, which the child then counts.

Errors: `404` for an unknown skill or learner, or a skill with no problems yet.

### `POST /api/lesson/problems/{id}/answer`
Check the child's answer (a whole number from 0 to 10,000).
```json
{ "answer": 80 }
```
Wrong, with a recognised mistake:
```json
{ "correct": false,
  "feedback": "The ones made a new ten! Let's swap 10 ones for 1 ten and add it to the tens.",
  "misconception": "forgot-to-regroup", "next_hint": "picture", "attempts": 1 }
```
Correct, after trying again:
```json
{ "correct": true, "feedback": "You kept trying and you got it. Well done!",
  "misconception": null, "next_hint": null, "attempts": 2 }
```
- `feedback` is what to show and read aloud to the child.
- `misconception` is for teachers. Don't show the id to the child.
- `next_hint` is the hint-ladder step to offer next: the checker's suggestion for a recognised mistake, otherwise `"nudge"`.

Errors: `404` if the problem isn't known, `422` for an invalid answer.

### `GET /api/lesson/problems/{id}/hints?start=nudge`
The hint ladder, from `start` (`nudge`, `picture` or `worked-example`) onwards. It's the same every time for a given problem.
```json
[{ "step": "picture", "text": "Put the ones together. Can you make a new ten?",
   "visual": { "type": "base-ten", "params": { "a_tens": 7, "a_ones": 8, "b_tens": 1, "b_ones": 2 } },
   "example": null },
 { "step": "worked-example", "text": "Here's one I solved. Now you try yours the same way.",
   "visual": null,
   "example": { "kind": "add", "question": "41 + 19 = ?", "operands": [41, 19],
                "steps": ["Ones: 1 + 9 = 10. That's 1 ten and 0 ones.",
                          "Tens: 4 + 1 = 5, plus the new ten is 6.",
                          "6 tens and 0 ones is 60.", "So 41 + 19 = 60."] } }]
```
Visual types and their `params` are listed in `backend/services/hints.py` (`Visual`). For a `number-line`, `blank` is the position the child fills in, so **always draw that box empty**.

Errors: `404` if the problem isn't known, `422` for an invalid `start`.

## Learners

Learners and their progress are stored **only on this device**, in a local SQLite file (`DATABASE_PATH`). There are no accounts or passwords: anyone using the device can view or reset progress. See [CHILD_SAFETY.md](CHILD_SAFETY.md#data-and-privacy).

### `POST /api/learners`
Create a learner. Returns `201`.
```json
{ "nickname": "Simba", "avatar": "lion" }
```
```json
{ "id": 1, "nickname": "Simba", "avatar": "lion", "created_at": "2026-11-26T11:57:25+00:00" }
```
- `nickname`: **a nickname, never a real full name.** 1–20 letters (any language), with single spaces, hyphens or apostrophes between words. Digits and symbols aren't allowed, so phone numbers and email addresses can't be used. Must be unique on the device, ignoring case.
- `avatar` (optional): one of `lion`, `elephant`, `giraffe`, `zebra`, `cheetah`, `rhino`, `hippo`, `monkey`.

Errors: `409` if the nickname is taken, `422` for an invalid nickname or avatar.

### `GET /api/learners` and `GET /api/learners/{id}`
List all learners (by nickname), or get one.

### `GET /api/learners/{id}/progress`
Totals and mastery for each skill the learner has practised, most recent first.
```json
[{ "skill_id": "count-to-20", "status": "mastered",
   "problems": 5, "attempts": 6, "correct": 5,
   "recent_total": 5, "recent_correct": 4, "correct_days": 2,
   "last_practised": "2026-11-25T08:00:00+00:00" }]
```
- `status`: `practising` or `mastered`. Mastered means at least 4 of the last 5 problems were right **on the first try**, on at least 2 different local days (see [PEDAGOGY.md](PEDAGOGY.md#1-skill-map-and-mastery)).
- `problems`, `attempts` and `correct` are all-time totals, **including** retries.
- `recent_total`, `recent_correct` and `correct_days` show the numbers behind `status`, using first answers only.

### `GET /api/learners/{id}/next-skill`
The skill this learner should work on next. A **due review** comes first (one problem; see [spaced review](PEDAGOGY.md#6-short-sessions-quick-feedback-regular-review)). Otherwise it is the first skill in teaching order that isn't mastered yet and whose prerequisites are all mastered.
```json
{ "skill_id": "add-within-10", "name": "Add within 10", "grade": 1,
  "status": "not-started", "review": false,
  "reason": "Ready to start: all the skills it needs are mastered." }
```
- `review`: `true` for a quick review of a mastered skill that is due. Ask for a problem for that skill as usual; once it is answered, the review is done.
A new learner gets the first skill (`count-to-20`). When every skill is mastered, `skill_id` is `null` and `reason` says so.

A learner's latest [placement check](#placement-check) also counts: the skills it found known are treated as mastered, until the learner gets one of them wrong on the first try after the check.

### `GET /api/learners/{id}/reviews`
The review schedule for each mastered skill, soonest first. For teachers and parents.
```json
[{ "skill_id": "count-to-20", "name": "Count objects to 20",
   "last_seen": "2026-11-05", "streak_days": 3, "due_on": "2026-11-12", "due": false }]
```
- `last_seen`: the local day the skill was last answered (or placed by the check).
- `streak_days`: days with right first answers in a row. The gap after `last_seen` is 1, 3, 7, 14 or 30 days.

### `DELETE /api/learners/{id}/progress`
Delete all of the learner's problems, answers and placement checks, but keep the learner. Returns `204`.

### `DELETE /api/learners/{id}`
Delete the learner and **everything** stored about them. Returns `204`.

## Placement check

A short adaptive check (at most 8 problems) that finds where a learner really is, so they start at the right level. See [PEDAGOGY.md](PEDAGOGY.md#2-teach-at-the-right-level-not-the-right-grade). No AI is used.

### `POST /api/learners/{id}/placement`
Start a new check. Returns `201` and the first problem. Any unfinished check for this learner is left behind.
```json
{ "placement_id": 1, "finished": false, "message": "",
  "problem": { "id": "3f9c2a1b7d4e5f60", "skill_id": "make-10", "kind": "missing-addend",
               "question": "6 + ? = 10", "operands": [6, 10] },
  "problem_number": 1, "max_problems": 8, "result": null }
```

### `POST /api/placement/{placement_id}/answer`
Answer the current problem. Returns the next problem in the same shape, or the result when the check is finished. The child is **not told** whether the answer was right.
```json
{ "problem_id": "3f9c2a1b7d4e5f60", "answer": 4 }
```
When finished, `problem` is `null` and `result` is set:
```json
{ "placement_id": 1, "finished": true, "message": "All done. Thank you! Now let's start learning.",
  "problem": null, "problem_number": null, "max_problems": 8,
  "result": { "placement_id": 1, "finished_at": "2026-11-27T08:10:00+00:00",
              "stop_reason": "all-decided",
              "known_skills": ["add-within-10", "add-within-20", "count-to-100", "count-to-20", "make-10"],
              "next_skill": { "skill_id": "place-value-tens-ones", "name": "Tens and ones", "grade": 2,
                              "status": "not-started", "reason": "Ready to start: all the skills it needs are mastered." } } }
```
- `stop_reason`: `all-decided`, `enough-problems` (reached 8), or `struggling` (stopped early after 3 wrong answers).
- `known_skills` count as mastered for [`next-skill`](#get-apilearnersidnext-skill).

Errors: `404` if the check doesn't exist, `409` if it is already finished or `problem_id` isn't the current, unanswered problem.

### `GET /api/learners/{id}/placement`
The learner's latest finished check (the `result` object above). Re-running the check replaces it. `404` if there is none yet.

## `POST /api/tutor/ask`
Ask the tutor a free maths question. This is the secondary "ask a question" mode. The main lesson API is planned (see [ROADMAP.md](ROADMAP.md)).

**Request**

| Field | Type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `question` | string | yes | — | The learner's question. 1–500 characters after trimming surrounding spaces |
| `grade` | integer | no | `GRADE_LEVEL` (`2`) | Grade level used in the prompt. Must be 1–3 |

```bash
curl -X POST http://localhost:8000/api/tutor/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is 14 + 5?"}'
```

**Response `200`**
```json
{ "explanation": "Let's count on from 14: 15, 16, 17, 18, 19. ... = 19" }
```

**Errors**
- `422`: the body is invalid: `question` is missing, empty, only spaces, or over 500 characters, or `grade` is outside 1–3. The model isn't called.
- `503`: the local model can't be used. The `detail` field says why and how to fix it:
  ```json
  { "detail": "Cannot reach Ollama at http://localhost:11434. Is it running? (`ollama serve`)" }
  ```
  ```json
  { "detail": "Model 'qwen2.5:1.5b' is not installed. Run `ollama pull qwen2.5:1.5b`." }
  ```
- `504`: the model took longer than `OLLAMA_TIMEOUT` seconds to answer:
  ```json
  { "detail": "The tutor took longer than 120 seconds to answer. Try again, use a smaller model, or raise OLLAMA_TIMEOUT." }
  ```

## Configuration

Set these as environment variables or in `backend/.env` (see `backend/.env.example`).

| Variable | Default | Description |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Where Ollama is listening |
| `OLLAMA_MODEL` | `qwen2.5:1.5b` | Model tag passed to Ollama |
| `OLLAMA_TIMEOUT` | `120` | Max seconds to wait for a model reply before returning `504` |
| `GRADE_LEVEL` | `2` | Grade used when a request doesn't send one. Must be 1–3 |
| `CORS_ORIGINS` | `["http://localhost:5173"]` | JSON list of allowed frontend origins |
| `DATABASE_PATH` | `backend/data/math_tutor.db` | Local SQLite file for learners and progress. Never commit it |
| `TIMEZONE` | `Africa/Nairobi` | Time zone for counting "different days" in the mastery rule. Must be a valid zone name |
